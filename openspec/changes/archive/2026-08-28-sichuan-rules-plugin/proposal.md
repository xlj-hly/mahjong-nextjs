## Why

第一层用国标麻将跑通了「规则无关核心 + 规则插件接口」的架构，但这个架构**只被一种规则验证过**。设计里明确承诺「加第二种规则不改核心」——如果这个承诺不成立，后续加日麻、加任何规则都要改引擎，插件化就是空谈。因此现在用四川麻将作为第二个插件，做一次实战验证：要么证明接口够用，要么把接口的缺口暴露出来并做最小修复。

## What Changes

- 新增**四川麻将规则插件** `sichuan-rules`：108 张牌种（无字牌、无花牌）、不能吃（仅碰杠）、缺一门约束、四川番种体系、和牌判定与结算。
- 四川规则的核心约束是**缺一门（定缺）**：发牌后每位玩家声明一门花色为「缺」，之后该门牌不能碰、不能杠、和牌时手牌不得含缺门牌。这是国标没有的「玩家级局内状态」。
- 为支持缺一门，对 `mahjong-core` 的**动作合法性接口做一次统一升级**：把 `canPong` / `legalChow` / `kongOptions` 的窄参数（手牌 + 弃牌）升级为统一的 `ActionContext` 上下文（含座位、门风、圈风、缺门等局内状态），使动作判定与和牌判定一样都能访问局内状态。国标插件仅需机械适配（忽略新增字段），规则逻辑不变。
- 状态机增加「定缺」流程：发牌后若插件声明需要定缺，则依次询问每位玩家定缺，记录后进入行牌。
- 热座模式接上新插件，验证第二种规则能复用现有引擎与 UI。

## Capabilities

### New Capabilities

- `sichuan-rules`: 四川麻将规则插件——108 张牌种、不能吃、缺一门约束（碰/杠/和牌三处）、四川番种体系、和牌判定与结算。

### Modified Capabilities

- `mahjong-core`: 动作合法性接口升级为统一 `ActionContext` 上下文；`WinContext` 增加缺门信息；状态机增加定缺流程。

## Impact

- **代码**：新增 `src/game/rules/sichuan/`；`src/game/core/rules-plugin.ts` 与 `state-machine.ts` 接口升级；国标插件适配新签名；热座 UI 增加规则选择与定缺交互。
- **接口**：新增 `ActionContext`；`canPong`/`legalChow`/`kongOptions` 签名改为接收 `ActionContext`；`WinContext` 与 `ActionContext` 各增加 `voidedSuit` 字段。国标插件需适配新签名（机械改动），但规则逻辑不变。
- **测试**：新增四川规则插件的和牌/缺一门/番种单测，以及热座定缺流程测试；国标插件测试适配新签名。
- **不改变**：国标规则行为不变；牌墙/拆解算法等核心逻辑不变。

## Non-Goals（明确排除，属后续 change）

- **血战到底**（一人胡牌后其余玩家继续打）：这是「一局如何结束」的流程差异，写死在状态机里（当前胡牌即整局结束），需要状态机层面的重构。本 change 仍采用「一人胡牌即结束」。
- **杠分即时结算（刮风下雨）**：杠牌当场计分的结算时机差异，属流程层，排除。
- **天胡/地胡**等低概率番种：首版四川番种表聚焦常见番种。
