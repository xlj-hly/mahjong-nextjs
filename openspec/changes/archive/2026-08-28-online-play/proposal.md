## Why

前两层已经交付了规则引擎（国标 + 四川）和热座对局，但「朋友自用」的最终目标是在各自设备上实时对战，而不是同屏轮流。第一层设计时特意把引擎与 UI 通过 `snapshot`/`apply` 两个口子解耦，并承诺「后续 WebSocket 复用引擎铺路」——现在是兑现这个承诺、验证「权威服务器 + 薄传输层」架构的时候。

## What Changes

- 新增**独立的 Node 实时对战服务**（Socket.io）：权威服务器持有对局引擎实例，所有规则判定在服务端完成。
- 新增**房间管理**：创建房间（生成房间码）、加入房间、准备/开始、四人满员开局。规则（国标/四川）在创建房间时选定。
- 新增**网络传输协议**：客户端仅上报意图（`apply`），服务端执行后向每个座位广播各自可见的 `snapshot`。
- 前端**热座切换为联机模式**：加入房间后，玩家在自己设备上看到自己的手牌，其余玩家手牌隐藏（与热座的快照语义一致）。
- 复用现有引擎（`Game`、`RulesPlugin`、国标/四川插件）与 UI 组件，**不改引擎核心逻辑**。

## Capabilities

### New Capabilities

- `online-play`: 实时对战的网络层——独立 Socket.io 服务、房间管理、意图上报与快照广播、联机对局。

## Impact

- **代码**：新增 `src/server/`（Socket.io 服务 + 房间管理）；`src/game/` 增加网络协议定义；前端新增房间/联机 UI，`useHotseatGame` 增加联机模式。
- **依赖**：新增 `socket.io`、`socket.io-client`。
- **运行**：新增 `npm run server` 启动服务端；前端 dev 时通过环境变量连接服务端地址。
- **不改变**：引擎核心（`Game`/`RulesPlugin`）、国标/四川插件、拆解算法均不改动；热座模式保留。

## Non-Goals（明确排除，属后续 change）

- **断线重连**：掉线后自动恢复对局。
- **观战**：第 5 人旁观。
- **账号/身份认证**：朋友自用，靠房间码加入，无登录。
- **匹配大厅**：无自动撮合，纯「建房 + 邀请加入」。
- **血战到底/杠分**等四川规则完整性：仍属规则层后续项，本 change 不涉及。
